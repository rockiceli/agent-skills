# canvas 程序化像素精灵（自动描边 · 图鉴风）

目标风格三条：**清晰轮廓 / 纯色阴影 / 短小四肢**。全部用 `fillRect` / `rrect` 画，不引入任何图片素材。

## 1. 核心招数：部件化 + 两遍绘制（描边 → 填充）

把一只角色拆成若干「部件」（头、身、耳、四肢、尾、翅…），然后：

```js
function paintParts(ctx, parts, line) {
  for (const it of parts) drawPart(ctx, it, line, 1);   // ① 每个部件膨胀 1px 画轮廓色
  for (const it of parts) drawPart(ctx, it, it.c, 0);   // ② 按数组顺序画各自的纯色
}
```

**为什么能得到一条干净的外轮廓**：膨胀（Minkowski 和 3×3 方块）对并集可分配 ——
`dilate(A ∪ B) = dilate(A) ∪ dilate(B)`。所以「先把每个部件膨胀一圈画深色，再把每个部件原样画纯色」= 整个剪影只有一圈外描边，**内部不会出现多余的接缝线**；而凸出去的耳朵 / 尾巴 / 翅膀天然自带一圈线。

部件只要三种图元就够：`rect`、`rrect`（膨胀时 `r+1`、宽高 `+2`）、`ellipse`（膨胀时 `rw+1, rh+1`）；尖耳朵用逐行扫描的三角（`w*(i+1)/h` 宽度递增）。

```js
const RR = (x,y,w,h,r,c) => ({k:'rr', x,y,w,h,r,c});
function drawPart(ctx, it, col, pad) {
  if (it.k === 'rr') D.rrect(ctx, it.x-pad, it.y-pad, it.w+pad*2, it.h+pad*2, it.r+pad, col);
  else if (it.k === 'e') D.ellipse(ctx, it.x, it.y, it.w+pad, it.h+pad, col);
  else D.px(ctx, it.x-pad, it.y-pad, it.w+pad*2, it.h+pad*2, col);
}
```

**需要“压在上面并自带折痕”的部件**（垂耳、鼓颊袋）走**第二遍** `over` 数组：
`paintParts(parts)` → `paintParts(over)`。第一遍里它们的轮廓会被后面部件的填充盖掉，放第二遍才有完整轮廓。

**不需要轮廓的东西**（眼睛、腮红、肚皮、花纹、胡须、天线）走 `deco`：在两次 `paintParts` 之后再画，纯色平涂。

## 2. 几何参数化：一套公式，四种变形

用「脚底中心点 (x,y)」定锚，其余全算出来：

```
legH = 3（会飘的角色 0 / 睡着 2）
bw = 12 + chub - min(2, slim)      // 体脂→宽度
bh = 6  + round(chub*0.4)          // 体脂→厚度
by = y - legH - bh,  bx = x - floor(bw/2)
hw = 15 + min(3, chub),  hh = 12
hy = by + 3 - hh                   // 头和身体重叠 3px → 剪影连成一体
hx = x - floor(hw/2) + (side ? dir*2 : 0)   // 侧面：脑袋往前探
```

- **体脂**：只动 `bw / bh / hw`，其余照旧 → 5 档体型不用画 5 套图。
- **视角**：侧面只改三处 —— 脑袋 `+dir*2`、尾巴甩到身后、吻部往前凸一个 4×3 的浅色块。剪影立刻不一样。
- **睡着**：`bw+=4, bh-=2, hh-=2, legH=2`。
- **表情**：只换 `drawFace` 的 mode（`''/happy/sad/sleep/effort/eat`），五官全画在 `hy + hh*0.34` 那一行。

`floor()` 而不是 `round()` 取半宽，左右才严格对称（眼睛间距才不会歪）。

## 3. 色板结构（8 只角色别只给 3 个颜色）

每个物种给一组语义色，风格才统一：

| 字段 | 用途 |
|---|---|
| `line` | 轮廓色（比 body 深、同色相；浅色角色也要给够对比，别用近白） |
| `body` | 主体纯色 |
| `body2` | 纯色阴影（身体下沿 1px / 下巴 1px，**不用渐变**） |
| `belly` | 肚皮 / 口鼻 / 手套 / 脚垫 |
| `inner` | 耳内 / 角 / 翅膀 / 附肢 |
| `spot` | 花纹 / 黄铜件 / 灯 |
| `eye` | 瞳色 |

## 4. 踩坑清单（血泪）

1. **1px 宽的细部件加了描边会变成 3px**：天线、触角、须这类细杆，膨胀后粗得像犄角。→ 改走 `deco`（不描边），或者干脆加粗到 2px 再把长度缩短。
2. **大块浅色肚皮会吃掉脸**：肚皮补丁如果从 `by+1` 起，会盖住头身重叠区（下巴），看起来像一张糊住下半脸的白面具。→ 肚皮一律从 `by+3` 起（只占身体下半），吻部放在**眼睛下面一行**（`hy+hh-5`）。
3. **装备 / 花纹别压在眼睛那一行**：眼睛在 `hy+4..hy+6`，头带放到 `hy+1`，护目镜放到 `hy`，尾巴别画到脸前面。
4. **换尺寸后要顺手挪“周边 UI”**：角色从 14px 长到 19px 后，别处按旧高度算的血条 / buff 星 / 头像缩放（`ctx.scale`）会正好压在头上，得一起调。
5. **时间驱动的眨眼/闪烁会毁掉截图**：`Math.sin(t*1.55+2.2) > 0.975` 这类瞬时状态，随手挑的 `t` 很容易正好落在区间里，于是**每一张**截图都是闭眼帧。→ 算一下 `sin`，给相位加偏移，让常用截图时间点落在稳定态。
6. **改大段绘制代码要整段替换**，不要分段插 —— 容易删掉旧变量（`bob`/`bw`）却留着还在引用它的尾巴代码，文件语法直接不通。

## 5. 验证方式（两件套）

1. `node tools/smoke.js`：用 vm + DOM 桩把绘制跑一遍，遍历 **物种 × 视角 × 姿态 × 表情 × 体型** 的组合，能抓出 `undefined` 之类的崩溃。
2. **做一个图鉴预览页**（`preview/species.html`）：一张卡 = 正面视图 + 侧面视图 + 三种表情缩略图 + 名称 + 描述 + 色板色块，页脚写风格三条。既给自己看，也是可以直接交付给用户的产物。
   - 缩放截图检查细节时，**一次只放 1~4 个对象**、`image-rendering: pixelated`、窗口刚好包住内容；堆成一张巨型 contact sheet 会被缩放到看不清像素。

## 6. 反过来：把「照片 / 已画好的画面」转成像素精灵

同一套精灵体系可以反向用 —— 用户上传照片、或者把游戏里已经画好的怪「拍快照」存档，都要落到同一个可序列化结构上。

**统一数据结构**：`{ w, h, pal: [hex...], px: '字符串' }`，`px` 每个像素一个字符，`pal` 下标用 base36（`0-9a-z`，上限 36 色，实际量化到 ≤16），`'.'` 表示透明。好处：JSON 直接存、体积极小、绘制时查表即可。

**流水线**（`pixelate(rgba, w, h, opt)`）：

1. **采样**：先把原图 `drawImage` 缩到目标尺寸（宠物 30×30 上下就够），再 `getImageData`。先缩放再量化，比先量化再缩放干净得多。
2. **去背景**：从四条边所有像素做**连通洪水填充**（容差 `bgTol` ~ 34），只吃掉与背景相连的区域 —— 不能全局按颜色抠，否则角色身上的白色也会被抠穿。
3. **量化**：median-cut（按通道极差最大的轴切、取框内均值）压到 `colors` 色（2~16）。比固定调色板配适应用户照片。
4. **裁剪** `trimSprite`：**先算包围盒再裁**，别边扫边裁。
5. **描边**：可选，给剪影外圈补一圈深色，让它在深色迷宫背景上也立得住。
6. **限制尺寸** `fitSprite(sp, max)`：整数倍降采样或裁剪到上限，存进存档前必做，否则一张 400×400 的照片会撑爆 localStorage。

**绘制** `drawPixels(ctx, x, y, sp, o)`：脚底中心锚点（和手绘精灵同一约定）、`dir` 翻转、**整数缩放**（非整数缩放会出摩尔纹）、按行做 run-length 合并相邻同色像素再 `fillRect`（一次 300 次填充能压到几十次）。

**接入现有 drawPet**：在函数开头加一句 `if (sp.custom && sp.px) { drawPixels(...); return; }` —— 手绘分支和像素网格分支共用一个入口，其余调用点不用改。

**踩坑**
- 真实浏览器才有 `getImageData`，Node 冒烟测试里要能降级（用造出来的假 `mkRGBA(w,h)` 数据测算法，用浏览器探针页测真实路径）。
- 验证真实路径时别把「摘要对象」当 sprite 传 —— 快照函数如果返回 `[summary, sprite]`，取 `sprite` 要单独存数组，否则 `custom:false` 却查不出原因。
