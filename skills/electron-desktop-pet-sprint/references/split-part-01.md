## 画装饰 / 特效的硬规矩

- `D.px(ctx, x, y, w, h, c)` —— **6 个参数一个都不能少**。少传 `h` 会把颜色串当高度，不报错但画错。
- 装饰（装扮）按 `part` 分发：`head / face / neck / back / aura / relic`。新增一件要同时改
  `DT.COSMETICS`（data.js）、`COS_CHARM` + `COS_STYLE`（desktop.js 里漏一个魅惑度就算 0）、`D.drawGear` 的分支。
- 气焰 / 翅膀走 **包围盒** 而不是写死坐标：`D.petBox(x, y, G)` 取「头 ∪ 身 ∪ 脚底」的真实盒子，
  这样内建物种和上传的自定义形象（`sp.custom` 分支里手搓的 `G2`）共用同一套绘制，都能绕到位。
- 面板一行只能放一个按钮时用 `row()`；要放多个就 `rowMulti()`，带输入框就 `rowInput()`（第 9 个可选参数 `max` 是 maxlength，默认 8）。
- 想断言「形状是不是倒梯形 / 逐行描的」：跑两遍 `drawPet`（带/不带该装饰），用 `x|y|w|h` 做**集合差**拿到只属于装饰的矩形，再按 `y` 分组求每行总宽 —— 比断言具体像素稳。
- ⚠ **派生表要在数据源改完之后重算**：`D.COSMETIC_KEYS` 曾经在 `D.RELICS` 塞进 `COSMETICS` **之前** `Object.keys`，结果 4 件圣物永远不进面板 → 戴上就没有「摘下」按钮（不报错、纯静默）。
- ⚠ **数值公式别把 `effLv` 当输入**：`effLv = 冠数×999 + 等级`，一乘进去就等于「突破两次 = 加成翻二十倍」。传世宝剑第一版就栽这上面（第 1 任给 +121 攻 / +906 血，Lv1 新生 948 血）。跨代累加的奖励一定要**配总量上限**（`ST.SW_CAP`）。

## 联网 / 外部接口的硬规矩（第 21 轮血泪）

- ⚠ **多源要铺在不同域名上**：以前 3 个「热搜源」全指向 `api.vvhan.com`，那域名一挂（实测 ENOTFOUND）三个一起死，所谓冗余是假的。
- ⚠ **每个源自己一个 AbortController** —— 共用一个的话，串行请求里前一个把后一个的时间全吃光，后面必然超时。
- 免登录实测可用的热搜接口（2026-09-30）：`api.bilibili.com/x/web-interface/search/square`（→ data.trending.list[].keyword）、
  `api.zhihu.com/topstory/hot-list`（→ data[].target.title）、`top.baidu.com/api/board?platform=wise&tab=realtime`（→ data.cards[].content[].word）、
  `www.toutiao.com/hot-event/hot-board/`（→ data[].Title）。
- **B 站合集（多 P）的集数必须问 `api.bilibili.com/x/player/pagelist?bvid=BVxx`**，别往播放器里注入脚本用 CSS 类名猜 ——
  `player.bilibili.com` 那个纯净播放器**根本不渲染选集 UI**，猜出来永远是 0，合集就永远不跳下一集。
- 搜索接口 `search/all/v2` 和 `search/type` 互为备份，主接口挂了降级；同关键词结果缓存 5 分钟，别反复打网络。

## 写测试的硬规矩（第 21 轮两次踩坑总结）

- ⛔ **不许留假断言**：`is(x || true, '（保留位）')` / 为通过而把阈值放宽到噪声级 / `'TODO 以后再测'` —— 这些都等于没有断言。
  这一天连着踩了两次（「特点关经验」放宽到 3%、「loop 无条件打开」写成 `|| true`），两个真 bug 就在「1039 全绿」的状态下溜到了用户手里。
- ⛔ **断言失败先怀疑「测的东西对不对」，别急着放宽阈值**。放宽阈值是把真信号和噪声一起放过去。
- ⛔ **对「注入到别的上下文里执行的脚本」做断言时必须真跑一遍**，不能只 grep 脚本文本：
  文本匹配能被绕过（把条件改成 `if(0)` 它照样绿）。做法：造假 `document` / 造假 DOM 节点，
  `new Function('document','setInterval', 脚本源码)(fakeDoc, ()=>0)`，断言跑完之后对象状态符合预期。
- ✅ **写完新断言做一次反向验证**：故意把修复改回 bug 版本，确认断言真的变红，再改回来。
  这一步成本极低，但能把「根本没在测」的断言当场筛出来。
- ✅ 涉及异步（IPC / 网络）的断言要记得 `await S.flush()`，不然拿到的是旧状态。

## 第 23 轮踩过的坑（写测试时先看这段）

**① 沙箱里 `Date.now()` 是真时钟，`new Date()` 才是被钉死的那个。**
`TestDate extends Date` 只改了构造函数，**没有**改继承来的 `Date.now`。
所以新模块里凡是算「过了多久 / 今天第几次」，一律写 `new Date().getTime()`，
跟胶囊/时段那套保持一致。写 `Date.now()` → 测试里算出来的是「真实现在 − 钉死的 9-28」= 差好几天。

**② 日志只有 3 行（`pushLog` 里写死 `while (logs.length > 3) shift()`）。**
「播报了一条」不能靠 `D.logs().length` 变大判断 —— 满了之后长度永远不变。
要看 `D.logs()[D.logs().length - 1]`（最新的在最后），或者搜最近 3 行。

**③ 每个沙箱都重跑一遍模块 → `BD.gacha` 在每个沙箱里是**不同**的对象。**
别拿第一个沙箱的模块实例去操作第二个沙箱的状态（我第一版 `BD.gacha.paint()` 永远返回 0，
因为那个实例的 `sel` 还是 null）。哪个沙箱开的页面，就用哪个沙箱的模块。

**④ 测「夜里长睡」必须把钟拨到凌晨 2 点。**
六种习性的入睡/起床时间各不相同（21:30~23:30 睡 / 1:30~9:30 起），
凌晨 2 点是唯一一个「六种全在睡」的钟点。白天 10 点强行打 `nightSleep` 标记没意义 ——
idle 分支里那条「天亮了就叫醒」的兜底会立刻把它叫起来（那是对的行为）。
`makeSandbox({ now: <ms> })` 支持自定义沙箱时钟。

**⑤ 断言失败先怀疑前提，别改代码、别放阈值。**
这一轮 14 条假红里只有 4 条是真 bug，其余全是测试自己写错：档位边界记错、
超长字符串正好 30 个字（门槛是 >30）、新档 boot 时字段已经建好了（惰性初始化得手动删了再测）、
「老存档没有这个字段」的前提被 boot 自己破坏了。

**⑥ 旧断言会因为功能改版而假红 —— 那是前提过时，不是回归。**
角色变成皮肤之后【8】那节 11 条全红。正确做法是让那节先「解锁名册」再测它原本要测的东西，
而不是把门禁拆掉。

## 第 24 轮踩过的坑（抽卡 / 命名 / 存档边界）

**① 同一张图在存档里有两个 id：`as:<assetId>` 和 `cu:<cuId>`（靠 `custom.fromId` 互指）。**
两条都收 → 池子一半是同一张图的影子；而 `PT().currentKey()` 只返回 `as:<id>` → 「装备中」匹配不上。
统计任何「池子 / 收集度 / 羁绊门槛」之前，**先按 `fromId` 归一**（`aliasKey()` / `assetIdOf()` 双向解析）。
这类错误**不报错**，只是数字「看起来不太对」。

**② 多分支的「取名 / 取图」函数里，语义最具体的一支必须放最前。**
`heroNameOf()` 里 `as:` 分支排在抽卡表前面 → 素材角色永远被读成文件名（「换上还是显示橘猫1」的根因）。
`as:` 只说明「这东西来自素材库」，不代表「它叫什么」。

**③ 自动生成的值和用户输入的值永远不要共用一个字段。**
自动称号写 `pet.name`，用户手输的名字另存 `save.nick`；`applyHeroName()` 里 `nick` 存在就一个字都不动。
共用字段的后果是：每次系统刷新都把用户输入洗掉，而用户只会说「我的名字自己变了」。
老存档用 `healHeroName()` 自愈（**名字像自动生成的才修，有 `nick` 直接跳过**）。

**④ 重写一个已经 `bind()` 过的模块，第一件事是确认 `function bind(o)` 还在。**
`desk-gacha.js` 整块重写时漏掉了它 → 模块变空壳（收不到 `D/U/esc/save/PT/ST/A`）→ 四条门禁全红。
**少了 bind 不会有语法错误，只会静默失灵。**

**⑤ 断言「某段文字不该出现」是很弱的断言 —— 要数可数的唯一标记。**
「收起的那一档不该有皮肤标题」被我写成搜 HTML 文本，可**羁绊行和「最近抽出」行里也有皮肤标题** → 永远为真。
改成数 `[data-do="gachasel"]` 按钮：收起 = 3、全展开 = 70、再收起 = 3。
（按既定纪律**没有放宽阈值**，只换了测量方式。）

**⑥ 测「随机的东西」要先把它变确定，而不是把断言放宽到「偶尔也能过」。**
`statsOf 吃到 BGM 加成` 偶发红 —— `ST.bgmAdd()` 从 7 个键里**随机抽一个**，8 次规划可能一次都没抽到攻击类。
改成喂一个已知的 `bgm = {atk:12,def:8,spd:6,hp:20,crit:50,loot:.3,expb:.4}` 逐项对账
（注意 `crit` 在 `state.js` 里是 `/100`）→ 从此确定，连跑 4 次全绿。

**⑦ 截图脚本会污染存档 —— 而且 `localStorage.clear()` 洗不掉它。**
抽卡状态挂在 **desktop save 的模块内存**里（`gs()` 读 `BD.desktop.save()`），不是 `mochi-save-v1`。
症状：连跑几次「收集 41 → 44 → 48」一路往上飘。修法是注入里显式重置：
`ds.gacha = { owned:{}, pity:ds.gacha.pity, pulls:0, dup:0, equip:ds.gacha.equip, log:[] }`。

**⑧ 截图 / 探针脚本跑在哪个 profile（重要，可以放心用）：**
- `electron tools/xxx.js` → 默认 profile **`%APPDATA%/Electron`**
- 真机 `desktop/` → **`%APPDATA%/mochi-desktop-pet`**

两个 profile 的 localStorage **互不影响**，脚本也**不会写 `beast-diary/mochi-share.json`**。
验证方式：`ls -la --time-style=full-iso <profile>/Local\ Storage/leveldb`，脚本跑完之后只有 `Electron` 那个在动。
（第 24 轮为了确认「抽卡那几次到底写没写到用户的真存档」专门查过这件事。）

**⑨ 要截「稀有度折叠菜单」这类长面板，必须显式 `scrollIntoView`。**
面板是固定高度 + 内部滚动，`capturePage()` 只拿视口那一屏。滚动容器是 `#pgBody`，不是 `window`
（`window.scrollY` 永远 0）。悬停气泡要**手动造 `MouseEvent('mousemove', {bubbles:true, clientX, clientY})`
派发到带 `data-tip` 的元素上**，再读 `#tip` 的 `textContent` 验证。

## 第 25 轮踩过的坑（换肤改名 / 浮动弹窗 / 手风琴 / 真机上传形状）

**① 用户说「你上次修过了还是不行」→ 八成是修在了支路上，没修在统一出口上。**
第 24 轮已经把 `save.nick` 存好了，第 25 轮用户照样报「我取的名字还是会变成皮肤名字」。
根因：换肤路径有 **5 条**（换上 / 抽卡后穿上 / 候选确认 / 抽到新卡 / 脱下），
**统一出口只有 `applyHeroName(k)` 一个函数**，而它从头到尾**没读过 `save.nick`**。
做法：动手前先 `grep` 出所有写这个字段的地方，找到那个被所有人调用的出口，**判断只写一次**。
（第 24 轮那条说「两份存」，这一轮补：**光两份存不够，出口必须读。**）

**② 浮动弹窗不能做「会被整体重绘的容器」的子节点。**
`renderPage()` 每次重写 `pgBody.innerHTML` → 放进去的弹窗第一次重绘就没了。
`#gpeek` 必须是 **`#page` 的兄弟节点**，不是子节点；`z-index:80`（高于面板层 8~30，低于 `#tip` 的 9999）。

**③ `openPeek()` 必须在 `renderPage()` 之前调用。**
反过来被点的按钮已经离开 DOM，`getBoundingClientRect()` 全返回 0 → 弹窗飞到屏幕左上角。
